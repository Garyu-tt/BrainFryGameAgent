# Как подключить цифровую муху к игре

**Версия руководства: 2026-11-08.** Это экспериментальная система на базе реального *анатомического* коннектома дрозофилы и синтетической нейронной динамики BFB9000 R06.1. Коннектом не является «готовым игровым интеллектом»: перевод картинки/телеметрии в нейронные стимулы и обратное преобразование в кнопки пока разработаны нами как искусственные адаптеры.

## 1. Быстрый запуск (без настоящего коннектома)

Нужны Python 3.11+ и `numpy`. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m flygame server --demo --state-dir .flygame-state
```

В другом терминале:

```bash
python examples/arena_demo.py
```

Команда `--demo` запускает **64 полностью выдуманных нейрона**. Это проверка соединения API и сохранения памяти, не демонстрация биологического мозга.

## 2. Запуск с нашим коннектомом

Если у вас есть совместимый датасет из BrainWorkbench/BFB9000, укажите директорию:

```bash
python -m flygame server --graph /path/to/runtime/data --state-dir .flygame-state-real
```

Состав: `meta.json` с `N`, `edges`, `minWeight`; бинарный CSR `graph_w3.bin` (при `minWeight=3`); `neurons.bin` с таблицей типов. Исходные проверенные размеры: **165 122 нейрона, 10 511 038 анатомических связей**. Контрольная сумма исходного CSR: `c34efca42d074786e8fb4fe4b6723d5b15aa4d69be17b0cf457321cb2ac6e030`.

Не путайте с проектом HQ500M и BFB9000 human: у них иная топология. Датасет не включён в GitHub, потому что требуется отдельная проверка лицензии/происхождения и он весьма крупный. Само приложение **не загружает** данные из Интернета. При неверной схеме загрузка заканчивается ошибкой, не «тренировкой случайного мозга».

## 3. Протокол для любой игры

Запущенный локальный сервис принимает:

```bash
curl -s http://127.0.0.1:8765/health

curl -s http://127.0.0.1:8765/v1/step \
  -H 'Content-Type: application/json' \
  -d '{"observation":{"food":0.6,"threat":0.1,"obstacle":0.2,"novelty":0.7,"hunger":0.5,"fatigue":0.1,"reward":0}}'
```

Поле `observation` содержит **только** числа от -1 до +1. Отсутствующие значения равны нулю:

| Сенсор | Что должен передать игровой адаптер |
| --- | --- |
| `food` | близость доступной еды/ресурса |
| `threat` | опасность или враг рядом (0..1) |
| `obstacle` | преграда на маршруте |
| `novelty` | новизна окружения |
| `hunger` | потребность в энергии/ресурсах |
| `fatigue` | потребность восстановиться |
| `reward` | оценка **предыдущего** действия (-1..1), от игрового адаптера |

Ответ содержит `action` (`forward`, `left`, `right`, `interact`, `retreat`, `idle`), `step`, `spikes`, `neural_ticks`, `neural_readout` и `source`.

Движок игры самостоятельно решает, как воплотить команду: нажать клавишу, повернуть бота, сдвинуть объект, отказать в опасном действии. Муха **не имеет прямого доступа** к клавиатуре, сетевым пакетам игрового сервера или файловой системе игры. Это граница безопасности, а не ограничение интерфейса.

## 4. Minecraft

Пример `examples/minecraft_mineflayer.mjs` требует Node 20+ и `mineflayer`:

```bash
npm install mineflayer
FLY_MC_HOST=127.0.0.1 FLY_MC_PORT=25565 node examples/minecraft_mineflayer.mjs
```

Сначала запустите FlyGame HTTP (пункт 1 или 2), потом подключайте Mineflayer к **своему тестовому** серверу. Бот наблюдает примерную угрозу от пяти видов монстров, уровень голода и факт перемещения; переводит ответ в короткие команды вперёд/назад/вбок. Команда `interact` в этом примере ничего не ломает и не строит. Поиск еды, карта, инвентарь, добыча, крафт и PvP **пока отсутствуют**. Старый BrainFly R62 этим адаптером не запускается.

Для Factorio, Godot, Unity или собственной игры схема та же: отправить сенсоры → получить команду → выполнить её через **штатный API** конкретной игры → на следующем шаге передать награду. Не требуется внедрение в чужой процесс.

## 5. Вариант без HTTP

```bash
printf '%s\n' '{"observation":{"food":1}}' | python -m flygame jsonl --demo
```

Одна строка JSON на входе → одна строка на выходе. Режим удобен для стандартного ввода/вывода, Pipe и локальных плагинов. Для сохранения между запусками используйте `--state-dir`.

## 6. Память и ограничения

- Каждое обращение выполняет четыре нейронных шага; у модели есть возбуждение, следы активности, усталость и синтетическая модификация локальных энграмм.
- Сигнал `reward` подкрепляет предыдущий выбор через ограниченные Q-значения. Это инженерная гипотеза обучения, не доказанная биологическая пластичность.
- Каждые 10 игровых шагов по умолчанию сохраняются атомарный NPZ-файл нейронов и отдельный JSON-указатель. После аварии возможен откат до последнего завершённого снимка; сквозной транзакционной гарантии между игрой и мозгом **нет**.
- Контрольная сумма снимка проверяется при загрузке; повреждённый файл не заменяется молча свежим мозгом.
- HTTP доступен только на loopback (`127.0.0.1`). Для удалённой игры поднимайте отдельный авторизованный TLS-туннель — **не** открывайте порт 8765 на весь Интернет.
- Исходный граф читается без права записи. Личные состояния не публикуются.

## 7. Что делать дальше

Приоритет развития — не имитировать настоящую муху красивой анимацией, а построить качественную сенсорику (зрение, направление движения, расстояния), привязку групп моторных нейронов к действиям и измеримый игровой тест. Отдельно следует сравнить сохранение/перенос навыков между разными играми. Пока этот релиз предоставляет открытый интерфейс и проверяемый стартовый образец.
